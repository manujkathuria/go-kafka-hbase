# Agent working guide

This directory is the maintained working guide for our Go pair-programming collaboration. Keep it short, discoverable, and aligned with actual code and agreed decisions.

| Location | Purpose |
| --- | --- |
| [AGENTS.md](../AGENTS.md) | Project facts, scope, guarantees, and routing. |
| [Pair-programming agreement](standards/pair-programming.md) | Baseline collaboration and engineering judgment. |
| [Standards index](standards/engineering-standards.md) | Design expectations, selected by task. |
| `skills/` | Focused implementation and verification workflows; triggers are listed in AGENTS.md. |

## Maintenance responsibility

The user authorizes the assistant to maintain this guide as part of development. Update confirmed facts, paths, navigation, and agreed conventions when relevant work changes them. Remove stale or duplicate guidance; record the reason when a meaningful rule changes.

Discuss new rules that change architecture, guarantees, collaboration, or scope before treating them as agreed. Do not turn a one-off choice into a universal standard, invent approval requirements, or add speculative rules. Routine maintenance within the agreed approach does not need a separate conversational confirmation; tool permissions still apply.

Keep reusable standards here, project decisions in AGENTS.md/architecture, and code journeys beside their projects. Prefer updating an existing document over creating competing guidance. Add a skill only for a recurring workflow; design expectations belong in standards.

Read the baseline once, then load guidance by trigger. Reuse unchanged instructions already read. Verify links after moves and summarize material guidance changes to the user. User instructions take precedence.
